# Internal v1.0 evidence gate — issue #24 (task 3.10)

Requirement-to-evidence audit for the internal v1.0 release. Every
F01–F08 and F11–F12 acceptance criterion and every §8.2 gate
(GATE-M01–M08) is traced to a **reproducible passing result** under the
recorded selected fixture identity — or named outstanding, which keeps
its gate closed. The owner acceptance record this audit feeds is
`docs/decisions/v1.0-acceptance.md`.

**What this audit is.** A trace, not a claim. Each row cites the
committed evidence artifact (test file, recorded-run JSON archive,
decision record, or live read-back) that a reviewer can re-run or
re-check. Verified is treated as *intermediate*: a criterion counts
only when a passing result exists under the exact selected
host/runtime/model/skill/config/provider/repository fixture identity —
missing, failed, stale or unknown evidence keeps GATE-M01/M03 closed
(A1) and any failed gate or unresolved acceptance decision is no-go,
not waived for schedule (A4/A6).

**What it is not.** Not a live end-to-end delivery of the selected
endpoint — the full issue→preview→approved-merge run on
`luongnv89/money-mind` is this task's scope and is recorded
**outstanding** on named owner blockers (GATE-M02 below). Not a
live-GitHub fault run and not a proof against every possible security
failure — the fault evidence is the deterministic local-fixture suite
the MVP commits to. Not acceptance itself — the release decision is the
owner's act, recorded in `docs/decisions/v1.0-acceptance.md`.
